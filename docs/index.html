📓 AI 讀書筆記＆待辦事項萃取器

資管系課程作業｜自選主題：把雜亂的課堂筆記、會議記錄、讀書會逐字稿， 丟給本地 Ollama 模型，自動整理成重點摘要與待辦事項清單。

做了什麼

這支程式用 Python + uv 呼叫本地 Ollama 模型，展示 W6 課程教的「結構化輸出（Structured Output）」能力： 不是請模型自由發揮寫一段摘要，而是定義好一份 JSON Schema （標題、重點摘要、條列重點、待辦事項、主題標籤），強制模型的回覆必須符合 這個格式，程式再用 Pydantic 驗證一次欄位型別是否正確。

應用情境：同學每週要讀很多課堂筆記、小組會議記錄、讀書會逐字稿， 常常事後很難回想「那次到底講了什麼、誰要做什麼事」。這支程式可以 把一段雜亂的文字，自動整理成「重點摘要＋待辦事項清單（含負責人、 截止日、優先度）」，省下自己重新爬梳筆記的時間。

核心能力：結構化輸出（Structured Output）
模型來源：本地 Ollama（免費、不需要 API 金鑰）
已處理範例筆記：3 份

怎麼執行

  1. 安裝 Ollama， 啟動服務後執行 ollama pull qwen2.5:7b（或你想用的其他模型）下載模型。
  2. 安裝 uv， 在專案資料夾執行 uv sync 安裝相依套件。
  3. 複製 .env.example 為 .env，依需要調整 OLLAMA_MODEL 等變數。
  4. 執行其中一個指令：
# 處理單一筆記檔案
uv run python -m notes_extractor run data/samples/lecture_data_structures.txt

# 一次處理 data/samples/ 底下全部筆記
uv run python -m notes_extractor run-all
  1. 重新產生這個作品頁： 
    uv run python scripts/build_site.py
  2. git add / commit / push 到 GitHub 的 main 分支， GitHub Actions 就會自動把 docs/ 部署到 GitHub Pages。

本地 vs 雲端比較（加分項）

這個專案選擇呼叫本地 Ollama而不是雲端 API，以下整理兩者的 差異，說明選擇本地模型的理由。

比較項目本地 Ollama（本專案採用）雲端 API（OpenAI／Anthropic 等）
API 金鑰不需要，完全迴避金鑰外洩風險需要申請並妥善保管，放 .env
費用免費（僅耗電腦運算資源）依使用量計費
隱私資料不離開自己電腦資料會傳到第三方伺服器
速度／延遲取決於本機硬體，筆電跑 7B 模型可能較慢通常較快較穩定
模型品質開源模型中文能力已不錯，但略遜於頂級雲端模型目前最強模型多為雲端閉源模型
網路需求下載模型後可離線使用每次呼叫都要連網路
適合放進 CI？不適合，CI 連不到本機 Ollama可行，但要把金鑰放進 GitHub Secrets
建置／維運複雜度需安裝 Ollama、下載模型（佔硬碟空間）申請金鑰即可使用，不需安裝

詳細說明見 README「本地 Ollama vs 雲端 API 比較」章節。
